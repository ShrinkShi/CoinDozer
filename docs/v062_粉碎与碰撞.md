# v0.6.2 粉碎机与场景碰撞：交付及验收

## 规则

- 进入粉碎机有效区域的一颗蓝色矿石，只有在可以同时生成全部三枚金币时才转换。
- 其中一枚复用原矿石实体，其余两枚是新独立对象。金币可继续被推送、倍增或用于升级。
- 当资源数目接近 6500 时，转换条件为：当前活着的实体 + 待创建实体 + 2 ≤ 6500。未通过检查的矿石不计入产量，也不会改成金币。
- 岩石和粉碎机入口钢制导向栏建立静态 2.5D 圆形或胶囊形碰撞体，颗粒和载具底盘使用附近网格查询进行碰撞修正。低矮石块在物体底部高于障碍物顶部时不阻挡物体。
- 冲击音效、白光、火花和世界坐标 +3 反馈不改变金币结算数据。

## 自动验收

```bash
node tests/v062_mechanics.mjs
node tests/v061_economy.mjs
node tests/v06_progression.mjs
node tests/v051_mechanics.mjs
node tests/v041_controls.mjs
python build.py
```

- 同帧转换 100 颗矿石应恰好得到 300 个独立实体且统计准确。
- 剩余槽不足时转换被拒绝，原矿石保留蓝色；释放空间后完整转换。
- 圆形岩石和导向栏有可触达的阻挡轮廓，不产生非有限数。
- 原 v0.6.0/v0.6.1 升级与经济回归均保持通过。

## 仍需要人工检查

- 手机横向、纵向操作中，铲斗能否持续推动蓝矿穿过新导向结构；同时观察长时间堆积或局部卡死。
- 100 颗矿石依次送入粉碎机的真实轨迹是否稳定；确定性批量转换测试不等同于完整物理压力测试。
- 岩石/护栏的碰撞只近似真实形状；车体前端、铲斗尖端和金属锯齿仍可能存在小幅穿模。
- 大量活跃资源下的帧率、碰撞求解预算继续留给 v0.6.3。
