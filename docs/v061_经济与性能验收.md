# v0.6.1 经济循环与性能观察验收

版本目标：增强早期资源可达性，建立产金/消耗可追溯数据，同时避免在接近 6500 个真实资源时继续自动补货。

## 已实现

- 42 枚真实新手金币，保留 1 金币 = 1 可见实体。
- 15 秒检查补货，受全局容量（5590 实体）及种类缺口共同约束。
- 双向 ×2～×20 门、粉碎 1→3、站点实物投币、旧存档兼容均未改变。
- 生产统计仅记录粉碎得到的新金币和倍数门额外创造的新金币，不将初始矿堆、自动补货算为“赚取”。
- 调试面板 F3/触屏可开关；帧率是实时渲染估算，不代表手机基准结果。
- 回收计数带销毁物体但不提供金额；既不悄悄回收也不生出幽灵钱包。

## 验收项

1. 完整装载后新手金币不少于 42 个。
2. 当金币与矿石补给量低于阈值时才补充真实实体，单次补充不超过各自批量限制。
3. 到达 5590 个实体暂停补货，任何已有对象都不应被自动合并或删除。
4. 金币通过倍数门增加实体、矿石被粉碎产金币后，面板统计反映正确数量；手工投入升级台时按当时币值统计金额。
5. 秒级滚动窗口会淘汰 60 秒以前的速率事件，但保留本局总量记录。
6. 四方向控制、倍率、金币升值、升级消费、双指及滚轮缩放不回退。
7. GitHub Actions 数值测试通过后才允许构建静态产物并发布。

## 未完成 / 风险

- 本轮未重新定价：真实玩家从零到首次改装是否能在 30～60 秒内完成，需要收集真机游玩时间后再确定。
- 保留现有 6500 物理实体上限。手机帧率可能下降；v0.6.3 再处理碰撞预算、GPU 渲染效率和长期运行稳定性。
- 休眠物理只是节流，不是完整三维刚体模拟。金币高速碰撞与粉碎轮路径问题将在 v0.6.2 继续改善。
