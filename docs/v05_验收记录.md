# CoinDozer v0.5 功能验收

## 变更依据

用户反馈 v0.4.1 中粉碎轮无法正常矿石→金币；门的逻辑 `weight` 聚合不能体现真实倍增；旧倍率 ×10000 太大；升级需靠近站点投入实物金币；希望电脑滚轮、手机双指改变镜头距离。

## 根因与处理

1. 旧粉碎逻辑：极小概率在特定时间片随机 `dead=true`，未生成金币。修复为蓝球接触旋转轮区域后**变更同一实体的 `kind` 为 `gold`**，位置、速度连续且有出轮组的推动冲量。保持 1 → 1 实物。
2. 旧门逻辑：创建对象数量受 32/9 等上限约束，超额使用 `weight` 存储。这已删除。现在只接受 2～20 的整数倍数，实际产生 `factor-1` 个新实体，保留原有实体，且所有新实体都有独立的物理状态。达到 6500 容量时整个复制操作被阻止（入口资源退回，提示容量），不发生无提示截断。
3. 分离经济配置：升级站需车体距离站点中心 6.5 世界单位内，且金币位于站前投放带区域；每消费 1 枚实物金币则对应扣 1 费用。四阶费用 [150, 600, 2500, 6000] 是 Demo 调参值，不宣称广告原数值。
4. 站台展示的真实下一阶车辆用与玩家相同的模型渲染流程，模型等级及尺寸随升级切换；不再用白色方块雕像代替。
5. 相机正交缩放为 [0.52, 1.9]，滚轮向上和双指分开均放大；当第二根手指加入时暂停并重置单指移动输入，防止手势结束后继续行驶。

## 性能与精度边界

- 上限 6500 个实体，每枚独立显示、独立持有坐标和状态。采用 WebGL 实例化渲染，不使用外部贴图或资源聚合。
- 远处颗粒可休眠；全场资源过多时仅调度距离玩家最近约 850 枚进行每帧高频碰撞约束。其余颗粒仍在画面中，不会消失、合并，也不会虚增逻辑数量；靠近玩家会重新进入求解。
- **这些颗粒不是完整物理引擎中的三维刚体**，因此很高的金币堆仍可能穿插、抖动或者变形。后续应优先改进接触性能和自动存档节流。

## 自动化验收

- `node tests/v05_mechanics.mjs`：门 ×2/3/5/10、资源上限、蓝矿转金币、升级站 proximity + 金币扣费、连续等级、镜头缩放方向及限位。
- `node tests/v041_controls.mjs`：控制方向回归（北东南西、铲斗/履带/物理方向一致）。
- `xvfb-run -a python tests/v05_browser.py`：390×844、1280×720 渲染、滚轮、双指张合、单指控制释放、WebGL 页面异常。

测试用的 SwiftShader 属于软件 GPU，不能准确代表用户 Android 真机帧率。下一步仍需由真机体验验证手感与长时间运行内存情况。
