## A. 视频证据与解释边界

## B. 当轮游戏验收（可直接操作）

- [x] 纯静态部署：运行时无服务器、无 CDN、无远程 API。
- [x] 单独的 `src/` 项目结构 + 自动打包至 `dist/index.html`，离线文件可直接打开。
- [x] 手机触屏拖动 / 电脑键盘控制，正交跟随相机。
- [x] 黄履带机、开放式绿头盔驾驶员和宽铲斗；后期车型预览。
- [x] 资源作为场景实体留在地面，不直接放进背包。
- [x] 近似铲斗推动、资源间局部碰撞、边缘抛散、行驶履带印。
- [x] X10 克隆可见球体；X10000 使用聚合粒子保留真实逻辑倍数。
- [x] 橙色滚刺障碍、岩石、熔岩、木桥、计数跑道、仓储装置、升级站。
- [x] 2500 升级费用逐枚扣减并有升级触发；周期刷新补足资源。
- [x] 手机竖屏/电脑横屏脚本验收、X10 数值与升级状态测试。
- [ ] **视频帧级镜头对齐**：以 00:18、00:22、00:36 为对照锚点，校正相机俯角、角色屏幕占比与各地标相对位置。
- [ ] **可视化物理堆积**：用独立碰撞层/堆高处理金币推成环、浮出铲斗并掉落；不能只是 2D 平面挪动。
- [ ] **模型细节**：铲斗真实曲面、履带齿、油缸、座椅、防护架、操作者、升级后红筒。
- [ ] **美术表现**：有环境遮蔽的阴影、金币浮雕、蓝球花纹、珠光、岩石材质变化，优化 lava shader。
- [ ] **特效**：漂浮烟雾、熔岩火花、刷轮碰撞粒子、资源飞溅、升级成套动画。
- [ ] **升级机制推断排查**：确认金币投入、计数跑道、解锁门之间实际关系；目前仅做出可玩的临时规则。
- [ ] **高阶阶段完整流程**：将多机型和后期 ×10000 场景按录像可解释的顺序连接，而不止菜单预览。
- [ ] **移动端低性能档**：至少目标 30 FPS / 中端手机，保证大量实例不触发 WebGL 上下文丢失。

## C. 质量门槛（计划）

**视觉**：先做到同场景、同相机、同车体朝向、相近元素屏幕占比，再进行材质与粒子表现对照。用同尺寸截图人工逐项核对，禁止只依据概念描述判断是否“足够像”。

**玩法**：在没有原游戏完整输入数据的前提下，以录像中确实可见的推、聚、溢出、撞刺轮、穿门增殖、金币投入、升级反馈为准；其余机制必须标记“推断”。

**工程**：不要为最后阶段引入服务器、账号系统、在线资产，保持构建后只有静态文件。建议后续仍保留独立原子测试，避免外观修复破坏碰撞或升级循环。
