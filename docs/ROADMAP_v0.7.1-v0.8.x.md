# CoinDozer 开发路线图：v0.7.1—v0.7.5 与远期产业链

> 状态：已确认的产品方向，2026-11-15。本文是需求基线和分版验收标准；未标记“已实现”的功能均非当前游戏能力。代码实现以各版本独立 PR 和 CI 为准。

## 总体原则

本轮五个版本**只打磨第一关冰河矿场**。第二关保留 v0.7.0 已存在的冰雪矿区和历史进度兼容，不扩建新玩法；进入第二关的新门槛留待自动化生产系统成熟后单独迁移。第一关的核心循环是：

1. 玩家驾驶铲车收集蓝色原矿；原矿在唯一数字门**双向实体倍增**。
2. 矿石跨越冰河主桥，进入北岸粉碎门；加工结果必须是可追踪的实际物体，而不是隐藏数字。
3. 玩家用金币在专用实体站台支付，升级车辆、数字门、粉碎门、主桥、金币价值及下一关桥。
4. 后期购买实体货箱、固定路线传送带，逐步实现真实运输和自动化。

不可妥协的不变量：
- 一个物品在任意时刻只有一个权威状态/所有者；散落、拾取动画、装载、支付动画、消耗不可同时存在。每枚车载金币仍有独立 ID、面额、渲染位置。
- 运输/装车不产生或销毁物品；倍增与加工是**有原因且原子性**的数量变化；每个产物都是真实独立对象。不得合并显示为“×N”虚拟资源。
- 游戏保持最多 6500 个活体实体，超过容量时阻止原子加工或倍增，保留原料，不得以悄悄清理资源来掩盖性能问题。
- 场景、实际碰撞、支付触发区域的坐标共用工程参数，更新车辆和资源都能正确通过的桥梁。
- 存档延续 `coindozer-progress-v06` 兼容，不允许升级后丢失已购等级。
- 自动化不允许跨越上锁桥、穿冰河或瞬间把资源传送到目的地；后台场景可以做有据可查的低频产能结算，但前台场景必须遵守真实实体规则。

## v0.7.1 — 长地图实际可玩性修复（本次开发）

范围：
- 修复南/北两岸及两座桥的车辆与颗粒通行判定：禁止跨帧高速穿河、对角绕过桥头、锁桥旁通行；更新桥宽时几何与碰撞保持一致。
- 数字门：加强快速斜向穿越时的入口判定，并保留旧冷却/重入保护。
- 粉碎门：排查上料、满载退回、出币区域和实体数量守恒；保持粉碎后金币全部独立存在。
- 实体升级台：高速掠过投币区域时不漏触发；超出台面高度、原地预置资源不应被错误扣费。
- 改善驾驶镜头与长距离导航：可收起的程序化迷你俯视图和目的地指引，跨河路线应指向桥梁；不改变经济数值。
- 加入针对性的 Node 物理回归、移动 Chromium 启动/导航/实际经济事件测试；保留离线 `dist/index.html` 自动构建一致性检查。

完成条件：可以正常驾驶完成“采矿→单门倍增→过桥→粉碎→拿金币付费”；两条冰河不可越界；金币与矿石不会因非法物理或支付重入消失。CI 不能证明安卓真机长期 FPS 或主观手感，必须另做实机试玩。

**非范围**：本版本不开发货箱、传送带、NPC、交易所，也不增加第二关内容和自动化通关门槛。

## v0.7.2 — 铲车车尾实体货箱与金币物流

- **容量等级**：开放式车尾货箱容量为 20 / 40 / 70 / 110 / 160 枚独立货币实体。当前初始升级信用价格为 25 / 55 / 110 / 240，需后续根据试玩再平衡。
- **自动装车**：铲车周围 3.25 单位内、低高度的本关货币会飞入货箱；每枚币分配稳定 ID 和独立槽位，最多 4 枚并行动画。没有虚拟钱包或合并显示。
- **车载物理**：存储和传输中的货币保留在全局资源数组并计入 6500 实体上限，但不进入自由颗粒物理接触；每帧按车体局部坐标更新位置。金币在货箱内随车移动。
- **支付事务**：车辆靠近有效升级台时最多 4 枚并行飞出，飞抵站台后才调用原有支付逻辑。多个币同时在途时若升级台先满级，剩余币返回原货箱槽位；站台满级时不再启动支付动画。
- **分关卡存档**：`cargoByStage[0/1]` 分别保存金币/金锭；装入或卸出开始时写入，刷新后所有未结算在途物品恢复为货箱内状态；支付与存档在同一同步帧提交。
- **旧档迁移**：沿用 `coindozer-progress-v06`，没有货箱字段的旧存档自动获得初始 20 格货箱。第二关金锭使用相同运输系统。
- **验收**：容量边界、ID 唯一性、调度器排除车载实体、装车/卸车、站台满级退款、刷新恢复、第二关货币类型与浏览器 UI 均需自动化覆盖。

## v0.7.3 — 升级成长深化与固定工位传送带

- 六种升级都应有对应的机械/外观变化、可解释的价格和能力收益；粉碎增产、门倍数、桥宽和金币价值必须影响真实经济或几何行为。
- 不做自由铺设。只在地图预设工位建造传送带：矿石上料→数字门→中央桥前后交接→粉碎机入口，以及金币出料→装车区。
- 传送带需要金币建设，并可升级宽度、速度、输送长度。对实际独立物体施加可解释的接触/输送作用，不使用传送瞬移或后台虚构资源。
- 传送带不能绕开桥梁，也不能让 NPC 成为更差的传送带替代品。
- 用程序化策略模拟+人工试玩校准早期/中期升级回报，不先承诺未经测量的分钟数。

## v0.7.4 — 第一关画面、物理与驾驶精修；NPC 技术验证

- 系统性检查和重构车体/铲斗几何、接触与阻尼、斜向矿石堆积、硬体相互作用、履带运动、传送带接触及动画。
- 优化场景比例、材质、接触阴影、桥与冰河层次、粒子/音效反馈、动态镜头与升级演出；以移动端可承受的开销为前提。
- NPC 铲车先**验证单台样机**自主找矿→规划绕桥路线→推料→上料→卡住恢复。不承诺本小版本直接提供大规模雇佣/队伍升级。
- 单台 NPC 能稳定运行、低开销，才进入后续付费雇佣数量和升级系统设计。

## v0.7.5 — 手机端、存档、性能与第一关整体验收

- 优化竖屏虚拟摇杆、镜头、导航、货箱状态、升级台/传送带 UI、安全区；减少遮挡与误触。
- 完整验收物品状态守恒、车尾堆叠和支付动画、定点传送带、主桥与上锁桥、场景恢复、WebGL 上下文中断和旧档迁移。
- 选定安卓中端测试设备，以 **1000 活跃实体稳定 30 FPS** 为初期性能目标；3000/6500 实体进行单独压力测量，不能用 CI CPU 跑分替代手机实机。
- 第一关自动化应能通过一段无需手动驾驶的连续生产测试，作为后续第二关解锁规则的技术准备。

## 第二关解锁：暂不在 v0.7.1—v0.7.5 改门槛

拟采用“**完成基础自动化生产线 + 支付第二关桥的金币 + 驾车过桥**”作为后续版本的新门槛，而非要求把所有 NPC 或设备升到满级。基础自动化验收项：采矿上料、数字门运输、跨桥上料、粉碎机加工、成品收集；须连续稳定运行（如 120 秒，待实际评测）。现有 v0.7.0 仅付费开桥的规则在未正式迁移前保持不变，避免突然锁死旧存档。

当玩家在第二关活动时，第一关已建设好的设备应继续提供合理收益；前台关卡使用完整独立实体模拟，后台关卡按已建设设备的真实产能、原料和仓储容量低频结算，不在手机上同时运行多个完整世界。第二关开启后自动免费建完第一关并不作为默认方案，可开放使用已赚取金币支付的旧关卡自动扩建。

## v0.8.x 及远期：交易所与纵向加工产业链（暂不实施）

- 未来“金币”主要通过**交易所出售实物**获得，而非“粉碎机直接凭空产生货币”。所有商品可按规则售卖：原矿→粉碎矿→洗选精矿→（适用矿种的热处理）→精炼成品。
- 首轮经济**设计假设**：原矿价值 1，粉碎矿建议至少 20—25，洗选 100，热处理 400，精炼 1500。它们是拟议售价，不是已实现数值，更不是矿业市场行情。
- 不能单凭售卖单价断定加工最优：用单位时间收益、加工吞吐、损耗、运费、设备成本和能耗证明“只刷原矿”不是长期最优策略。
- **只有原矿可以通过倍数门**；金币和高价值加工品不得再次过门复制，避免经济循环套利。
- 高价值交易必须设计真实独立的金币**面额**（如 1/5/10/50/100），避免一个 1500 价值物品强制生成 1500 枚物体突破资源上限。面额不同是一枚独立有值金币，不是绘制一枚再显示“×100”来伪装 100 个物体。
- v0.7.2 就应为每件物品定义稳定 ID、类型、状态、归属、价值/面额，避免交易所上线时推翻物理与存档系统。
- 根据矿种选择适用加工工艺，并非任何矿石都必须经过煅烧。

## 版本纪律与变更约束

每版独立 PR，先验证旧版本所有回归，再新增可观察、可重现的验收。变更功能、价格或时间门槛须更新本文件和相关测试。不将“概念图、自动化脚本测试通过”误当作“真实移动设备已验收”。本路线图经用户确认，仅作为开发方向；含“建议、拟定”的数字与方案须在开发时再次检验。
