# CoinDozer / 铲斗矿场

基于用户提供的竖屏广告视频重建的**纯前端 3D 游戏**。当前版本 **v0.7.4**，仍属于逐步还原中的可玩原型，模型与物理并非原游戏资源或原游戏代码。

**在线试玩：** https://shrinkshi.github.io/CoinDozer/

**已确认的后续开发计划：** [v0.7.1—v0.7.5 与远期交易所、自动化产业链路线图](docs/ROADMAP_v0.7.1-v0.8.x.md)。

## v0.7.4 第一关物理精修与单台 NPC 样机（2026-11-16）

- **单台自主铲车样机**：第一关小地图下新增启动/停止按钮，默认关闭，不消耗金币、不计入雇佣数量、不写入长期存档。样机从真实矿石实体中选择目标，使用网格 A* 寻路与视线平滑，静态障碍、玩家位置和冰河均纳入路线约束；跨河必须经过已存在的中央主桥。
- **真实推料**：NPC 与玩家共用同一车辆运动、履带里程、铲斗曲面碰撞、颗粒接触、静态障碍和扫掠河岸碰撞。每个资源仍只积分一次，再依次接受多个车辆的真实接触；没有改写资源坐标的“吸矿”或后台库存。
- **脱困**：监测实际位移；连续受阻后倒车、清除旧路径并重新寻路，反复失败时暂时跳过当前目标。NPC 状态和完成/脱困次数可在导航面板查看。
- **车辆与物理精修**：增加车辆静止时的低位车体碰撞，避免停车后矿石穿进底盘；活动调度器同时唤醒玩家和 NPC 周边颗粒，避免 NPC 推料时只移动单体而邻近矿石休眠。
- **材质精修**：冰河增加程序化霜层、细裂纹和冷色高光；金属滚轮/导轨使用独立拉丝材质。NPC 采用蓝青色车体与顶部信标，保留同一车辆几何和碰撞尺寸。
- **兼容性**：不改变 coindozer-progress-v06 存档结构，不保存 NPC 雇佣或虚拟资产；第二关不新增功能，原有解锁条件不变。NPC 只在第一关存在。
- **验收**：新增 tests/v074_npc.mjs 覆盖主桥 A* 路线、玩家避让、障碍绕行、停车车体碰撞、NPC 默认关闭、真实原矿→数字门→主桥→粉碎机链路和倒车恢复；新增 tests/v074_browser.py 覆盖手机 UI、NPC 实际移动、履带反馈、存档隔离和关卡隔离。

**当前边界**：这是单台技术样机，不是完整雇佣系统。复杂矿堆中的长期稳定性、NPC 与玩家高频近距离交互、移动端长时间帧率、整关 120 秒无人值守产线尚需持续实机验证；材质升级也不等于完成逐帧广告像素级复刻。

## v0.7.3 五段固定传送带与真实实体自动物流（2026-11-16）

- **五个预设建造工位**：第一关设置原矿上料（南端矿堆→数字门）、南岸接驳、主桥运输、粉碎机上料、金币出料五段固定传送带。每段单独建设，不允许在空地自由摆放。建造垫位于相应地图区域，可通过工程小地图的导航目标找到。
- **必须携币支付**：每段设备各有 0（未建）至 4 级，建设与后续升级价格依次为 24、60、120、200 信用金额。仅在车辆靠近该段绿色投币工位时，车厢中已实际收集的金币飞出抵达后计费；菜单与地图标记不能免费建造。
- **设备性能由真实几何决定**：建成时基础皮带宽 3.6 世界单位、牵引速度目标 6.4 单位/秒；三级升级分别增加宽度、牵引速度和输送覆盖长度。最高宽度 6.15，速度目标 12.1；过桥皮带受到**主桥当前宽度减 1** 的额外约束。
- **真实资源输送**：建造后只对确实落在传送带接触范围内且离地不高的对应资源（前四段为蓝矿，第五段为金币）持续施加速度推力。原物体保持独立 ID，仍由原有颗粒物理决定碰撞、重力、数字门倍增、冰河通行和粉碎结果；传送带不生成金币、不瞬移矿石、不绕过冰河约束。
- **脱离玩家的物理唤醒**：传送带会唤醒自身区域内此前休眠的矿石，无需玩家始终站在附近，仍遵守已有每帧 850 颗活跃物体的调度上限。载货币及飞入货箱动画的资源不能被传送带抢走。
- **金币装车交接**：第五段把粉碎机产生的真实金币向北岸右侧装车区输送，**不直接替玩家支付**。玩家仍需靠近金币出料末端装车，再自行运输金币到各升级台。因而 v0.7.3 实现的是生产设备自动搬运的基础，不是闭环无人值守收入。
- **新旧存档**：继续使用 `coindozer-progress-v06`，以 `belts[0..4]` 保存各段投资；旧存档缺少字段时 5 段均为未建设，原车体、货箱、数字门、桥梁及第二关货币状态不变。当前第二关门槛保持原先付费开桥加驾驶穿越规则。
- **验收**：增加 `tests/v073_conveyors.mjs`，覆盖各等级几何、单体牵引、资源种类、空气/货箱排除、真实桥梁阻挡、装车支付、新旧存档、真实无驾驶矿石穿越数字门→主桥→粉碎机和金币守恒。新增 `tests/v073_browser.py` 进行手机 Chromium 端付款、建成可视、刷新恢复与第二关隔离验收。

**边界与后续**：未引入自由铺设、付费 NPC 雇佣或交易所。设备升级价格及早中期经济尚需真人试玩校准；自动化的连续 120 秒生产稳定性和完整第一关零驾驶闭环仍为后续验收目标。CI 运行时间不是 Android 实机 FPS。

## v0.7.2 车尾实体货箱与金币物流（2026-11-16）

- **实体货箱**：铲车尾部新增开放式货箱，容量等级为 20 / 40 / 70 / 110 / 160 枚。货箱升级在北岸车辆改装台购买，初始信用价格为 25 / 55 / 110 / 240（后续可按试玩数据调整）。
- **金币自动装车**：铲车周围 3.25 单位内、低高度的本关货币可逐枚飞入货箱。最多 4 枚同时执行装载动画；每枚资源保留独立 ID、类型和货箱槽位，不存在虚拟余额或合并渲染。
- **真实运输**：货箱金币作为独立资源计入全局 6500 实体上限，但由车辆局部坐标驱动，不参加自由刚体碰撞；移动时随车厢同步，物理调度器仍统计其活体数量。
- **逐枚支付**：车辆靠近有效升级台时，最多 4 枚金币并行飞向对应投币区域。动画抵达后才调用支付；如果站台在飞行期间升满，未支付的金币沿动画返回原槽位。
- **事务与存档**：货箱资源有稳定 ID，按关卡分别保存。装入/卸出动画开始时保存未完成货币；刷新后所有未结算金币恢复为货箱内状态。支付在同一帧完成扣除并写入存档，避免重复支付。
- **兼容性**：沿用 `coindozer-progress-v06`；旧存档自动获得 20 枚初始容量，既有升级、第一关与第二关货币隔离不变。第二关金锭也能装入货箱。
- **测试**：新增货箱容量、物品 ID 唯一性、物理调度隔离、装车/卸车/退款、关卡存档恢复、手机端货箱 UI 与支付链路测试。更新旧测试中“金币直接穿过站台即扣费”的断言：现在必须先装入货箱，再完成飞出动画。

**边界：** 本版没有加入传送带、NPC、交易所或第二关新内容；金币的单枚价值规则未改变。价格是当前实现的初始调参，不代表已完成长期经济平衡或安卓真机性能验收。

## v0.6.4 载具外观成长与镜头表现（2026-11-14）

本版围绕车辆的可视反馈和广告风格体验推进，不更改经济数值与矿石/金币物理规则：

- **每档底盘升级可见**：不同级别的侧面防护、上部甲板、驾驶棚和强化护栏逐步安装，颜色与装甲体量同步变化。
- **五条改装路线各自可见**：速度升级新增排气/引擎散热组件，转向升级增加左右液压控制部件，金币价值升级增加车尾硬币形计价组件，铲斗升级拓宽真实可见的铲口并增加刮齿，底盘升级强化车身。不再只在面板中看到数值变化。
- **履带与车轮动画**：采用独立的履带路径几何函数 `trackLinkPose`，每条履带由真实移动的链板组成。 `advanceTrackOdometer` 按实测移动距离与转弯角度分别驱动左右履带，停车即停止；转向时两侧差速，角色和实体计算不变。
- **铲斗反馈**：对物理接触反馈使用小于 7 cm 的衰减位移；不更换或移动真实铲斗碰撞体，降低视觉和碰撞判定偏差。
- **构图与镜头**：保留已有固定斜俯视方位与相机对准，新增“镜头：全景 / 特写”按钮及升级时短暂的近景聚焦，兼容原有滚轮和双指缩放；方向映射不因镜头模式改变。

## v0.6.3.2 移动端启动阻断修复（2026-11-14）

- 问题根因：原离线打包器移除 ESM import/export 后，直接将全部源文件放入同一个 JavaScript 函数作用域。`src/collisions.js` 和 `src/activity.js` 都声明了 `const CELL`，以及同名 `key`，从而使最终发布网页在 JS **解析阶段**报 `SyntaxError: Identifier 'CELL' has already been declared`。整份游戏脚本都没有执行，所以“进入矿场”按钮根本没有绑定事件。
- 解决方法：`build.py` 按真实依赖顺序为每个源模块生成独立作用域与明确的命名导出/导入绑定，彻底消除不同模块局部名称之间的全局冲突；依然只使用 Python 标准库，没有引入 npm 或 CDN。
- 新增 `tests/v0632_bundle_syntax.mjs`：以 Node `vm.Script` **解析实际产出的单文件 JS**，而不是只检查 `src/main.js`。CI 与 Pages 每次部署之前运行；另以 Playwright Chromium 模拟手机触摸点击「进入矿场」，断言说明弹窗关闭且无 JS 异常。
- 原有图形失败的错误提示移动到按钮旁，按钮保留重试能力；不再在菜单最底部显示错误并直接禁用按钮。若设备没有 WebGL，仍需要兼容浏览器，不能承诺所有设备都支持 3D。
- `coindozer-progress-v06` 存档、金币真实独立、6500 个资源上限、经济计算与操控手感均不变。

验证：`python build.py && node tests/v0632_bundle_syntax.mjs`；PR 另运行浏览器级启动测试。

## v0.6.3 千级实体性能优化（2026-11-14）

这次更新只改变 **计算调度、网格与渲染成本**，不改变实物资源数量、存档、升级费用、倍数门倍率及粉碎机 1→3 规则。资源上限仍是 **6500**，并未宣称支持 10000 实体。

- **动态资源空间索引**：活动筛选每个逻辑帧执行一次，并在物理子步之间复用。沉睡资源不会被删除；铲车靠近或附近资源移动时重新唤醒。保留最多 850 个活动颗粒求解预算，并监测预算溢出。
- **GPU 实例缓存**：实例矩阵直接写入可重复使用的 `Float32Array`。GPU 缓冲区按需倍增容量，常规帧通过 `bufferSubData` 更新，避免每帧整体重新申请缓冲存储。
- **视锥裁剪与独立 LOD**：只提交相机可见的实体；远处金币仍是 **一枚金币对应一个简化金币网格实例**，蓝矿同理用低面数球体。不会把多枚金币合成一个代表对象，金币物理和数值不受可见性影响。
- **移动端自动画质**：高 / 均衡 / 省电三档，按照连续一段时间测得的帧率切换像素比、远处模型精度、阴影距离和非核心火花/粉碎轮装饰。提供切换冷却，防止频繁震荡。实际矿石、金币和升级交易不受画质档位影响。
- **诊断面板扩展**：显示可见资源、休眠/未调度数量、活跃物理预算溢出、当前画质、绘制实例/批次数、GPU 实例上传 KiB。原有 FPS、产金率与实体总数保留。

## v0.6.2 粉碎机与实体碰撞（2026-11-14）

本版聚焦 **矿石→金币转换可靠性、真实散布和场景障碍接触**，不改变 v0.6.1 的价格、供给周期、倍数门成长曲线或存档键。

- 粉碎机增加 **两条可见钢制导向栏**，钢栏和岩石按实体轮廓建立轻量水平碰撞体；车辆底盘与岩石也会发生接触。采用空间网格寻找附近障碍，避免全量逐对碰撞。
- **一颗蓝色矿石必须完整转换成三枚独立金币**（原矿石变成第一枚，新增两枚）。三个金币从出口以不同高度、横向速度和自转状态抛散，附带短白光、少量火花、简短音效和靠近粉碎口的 +3 数值提示。
- **资源上限处理是原子操作**：如果不足两个空闲实体槽，矿石保持蓝色，不发生部分兑换；它被推回入口并短暂冷却，玩家可以投币或回收其他物体后重新粉碎。门的满额处理不变。
- 独立资源碰撞与静态障碍碰撞分开维护，后续 v0.6.3 可以单独优化休眠、区域索引和渲染。这里的碰撞是轻量 **2.5D 近似**，不是完整刚体求解，不宣称所有车体零穿模。

## 游戏规则

- 推土机推动蓝色矿石穿过倍数门，物体独立复制。门从两侧通过均有效；四座门各自从 **×2** 升至 **×20**。
- 每座门旁设有黑金色投币台：车靠近并把**实体金币**推入该站台，才会增加该座门的升级进度。六次升级倍率依次为 2→3→5→8→12→16→20，费用依次为 12、25、50、85、140、220。
- 蓝色矿石进入橙色粉碎轮，**1 颗矿石生成 3 枚实体金币**；金币可继续被铲车推动、经过倍数门。
- 右上角的紫色站台是载具改装站。点页面顶部的 **「改装」**，选择五条独立升级路线，再把实体金币推入这个站台；点击项目按钮本身不扣费。

| 载具路线 | 等级（最多） | 各次升级金额 | 效果 |
|---|---:|---|---|
| 底盘换代 | 4 | 30 / 90 / 240 / 600 | 替换车体形态并略微提速 |
| 行驶速度 | 4 | 18 / 38 / 72 / 120 | 每级提高最高前进速度 |
| 转向速度 | 4 | 15 / 34 / 62 / 105 | 每级提高对准摇杆方向的转向角速度 |
| 铲斗宽度 | 4 | 24 / 48 / 90 / 150 | 每级增加 17% 铲斗宽度，**模型和物理碰撞同步生效** |
| 金币价值 | 4 | 25 / 55 / 110 / 240 | 每枚金币升级金额依次从 1→2→3→5→8 |

“金币价值”是**金币抵扣升级金额的价值**，不是金币对象数量：一枚金币始终只是一枚可见的实体。高价值金币在支付时会按实际价值逐档抵扣，超出当前档的金额自动结转到下一档；某路线满级后不再消耗金币。

## 操作

- **手机**：触屏单指浮动摇杆；双指捏合/张开改变摄像机缩放；点击「改装」切换目标路线。
- **电脑**：WASD 或方向键移动，鼠标滚轮缩放，P / Esc 暂停。所有改装必须在场景中通过推金币支付。

## 技术实现与边界

- 使用程序生成的低多边形网格、自编写 WebGL 实例化渲染和轻量颗粒约束，没有 npm 包和外部 CDN。
- 门通过时按倍率真实生成资源，每个资源独立显示。场景最多 **6500** 个资源实体；接近上限时拒绝新倍增，不偷偷减少生成数量，也不采用数值聚合。
- 远离车辆的静止资源可休眠，附近资源接受近似颗粒碰撞；不是完整三维刚体引擎。移动端帧率取决于设备 GPU。
- 第二个「粉晶岩洞」场景目前仍是视觉预览，付费改装与门升级玩法集中在主熔岩矿场。
